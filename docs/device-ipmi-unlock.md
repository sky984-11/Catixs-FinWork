# 机柜 IPMI 密码查看保护

设备列表、详情、创建 / 更新响应（包括管理员）中的 IPMI 密码一律返回 `******`；覆盖设备属性、四节点及历史字段别名。普通设备响应新增 `can_unlock_ipmi`，表示当前账号是否具有原设备敏感信息查看资格，不代表已解锁。

详情和编辑页面通过“解锁查看”单独验证当前账号登录密码。每次仅返回指定设备 / 节点的密码，弹窗 60 秒后自动隐藏；关闭弹窗、切换目标、离开页面或浏览器切到后台时清除内存状态。明文不写入表单、localStorage 或 sessionStorage。没有本地登录密码的账号须先设置登录密码。

## API

`POST /api/v1/asset/device/ipmi-unlock`

```json
{"device_id":123,"node_name":"N1","password":"当前账号登录密码"}
```

node_name 可省略 / null，表示设备自身。响应：

```json
{"code":200,"msg":"OK","data":{"ipmi_password":"仅当前设备或节点的密码","expires_in":60}}
```

响应包含 `Cache-Control: no-store` 和 `Pragma: no-cache`。不产生全局解锁令牌；每次查看均须验证，后续普通设备接口仍返回掩码。

要求登录、此 POST 路由的 API 权限，以及既有设备敏感信息查看资格（管理员也必须二次验证）。400 密码错误或账号未设置登录密码；401 未登录；403 无权限或账号停用；404 设备 / 节点 / 已保存密码不存在；422 参数无效；429 15 分钟窗口内已达到 5 次失败验证。限速状态存储数据库，跨进程与重启生效。

## 保存、操作与审计兼容

- 更新设备时掩码解析为原密码，按节点名称匹配，防止保存 `******` 或节点调序后串用密码；新设备收到掩码时不保存掩码为真实密码。
- 已有密码的新值编辑仍沿用原权限。普通用户不能通过字段别名覆盖密码。
- `POST /api/v1/asset/device/redfish-probe` 新增可选 device_id。密码为掩码时，仅当地址和用户名与该设备已保存值完全匹配才在服务端复用凭据，采集结果不返回密码。
- 设备接口不记录请求 / 响应正文，保留操作账号、路径、状态等审计元数据。解锁成功单独记录账号 ID、设备 ID、节点名，不记录密码。历史日志通过日志列表查询时也对 IPMI 字段脱敏；不改写历史数据库记录。
- 本次保护针对接口下发与页面查看，不改变设备凭据的数据库存储格式。
