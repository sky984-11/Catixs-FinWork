# 按次施工运维报价

客户管理不再展示或编辑运维小时单价和报价币种。旧数据库字段和接口字段仅保留兼容，运维计价不再读取这些字段，历史记录已保存报价不丢失。

## 计划与记录报价

列表对自定义报价直接显示小时单价和待确认原因。历史自定义报价的结果为空或 pending 时，优先使用记录自身保存的规则、报价和现场费用重新试算展示。缺少规则快照且费用未确认时，与编辑及保存逻辑一致，使用该记录关联工程师的当前规则，并保留本次自定义单价、现场费用和免收项，结果注明 `basis: current_rules`；不覆盖已有规则快照、不改写数据库、不重算已确认合计。工程师确实未配置规则时仍显示明确的待确认原因。预览显示本次最低时长、步长及人工费公式。规则附加费用与现场费用同名时提示两笔均计费，可点击“仅保留现场费用”将对应规则费用 id 加入本次 `excluded_fee_ids`；不自动去重，仍可重新勾选规则费用。接口路由、权限及字段保持兼容。

记录自定义方式通过 Switch 切换一口价和工程师单价微调。列表“费用”读取本次保存的 `billing_result`（包括自定义报价和现场费用），并根据 `customer_pricing_snapshot.kind` 标明报价来源；工程师列表原“阶梯计费”列统一称为“计费规则”。

最低计费时长表示起步时长；计费步长表示分钟间距，向上补齐。正工时计费分钟为 `ceil(max(实际分钟, 最低分钟) / 步长) × 步长`：最低60分钟、步长30分钟时，工作1分钟按60分钟收费，144分钟按150分钟收费。工程师规则和自定义小时单价使用相同取整方式；一口价不受工时取整影响。

计划创建/更新、运维记录创建/更新均接收 `customer_pricing`：

```json
{"customer_pricing":{"kind":"fixed","fixed_fee":"500.00","currency":"USD","expenses_included":false,"note":"本次设备安装，含人工、交通及税费"}}
```

- `kind: pending`：报价待确认。
- `kind: internal`：本次使用工程师规则。
- `kind: hourly`：本次小时报价，填写 `hourly_rate`、`currency`，替换基础人工价或固定档位；工时最低值、取整、通勤、夜班等规则继续适用。不再与客户档案单价绑定，也不对每次议价设置工程师成本下限。
- `kind: fixed`：本次一口价，填写 `fixed_fee`、`currency`。不再叠加工时、通勤、夜班、紧急或工程师规则税费。报价可独立于工程师和起止时间确认。
- `expenses_included`：仅一口价使用。true 表示现场报销包含在报价中，明细保留但不重复累加；false（默认）表示现场报销另计。
- `note`：报价范围、含税与其他约定，最长1000字。金额为非负、最多两位小数，可空表示待确认；币种为 USD/CNY/GBP/EUR/HKD/SGD/JPY。

新施工统一默认工程师规则。运维记录报价提供“工程师规则 / 自定义”，自定义下选择“一口价”（fixed）或“工程师单价微调”（hourly）。单价微调填写本次人工小时单价及币种，仅覆盖本次基础人工价，不修改工程师档案；最低工时、取整、夜班和附加费用继续按规则计算，原固定档位改为按本次小时单价计算。标准小时规则首次微调时带入工程师原单价和币种。计划界面仍提供工程师规则和一口价。历史 pending 报价继续保留，接口保持兼容。切换客户时前端重置报价；同一客户不同施工可填写不同报价。计划完成后报价带入记录，现场可以继续调整。记录编辑省略或null报价时保留同一客户既有快照；计划更新省略报价时同样保留。刷新工程师规则不会覆盖本次施工报价。

## 通用附加费用（2026-09-24）

夏令时不使用固定月份、固定时差或服务器当前日期判断。地区仅映射到 IANA 时区名称；计算时使用施工日期对应的时区数据库规则，逐分钟转换当地时间，覆盖施工期间夏令时开始的跳时和结束的重复小时。南北半球及不同国家分别使用各自规则。时区数据库来自项目的 pytz 依赖，地区政策变化后需随依赖维护更新，并非在线实时获取政策。

运维记录不再展示时区输入和列表时区列。入场、离场仍填写北京时间；计价接口根据 `region` 自动匹配 IANA 时区，匹配成功时优先于旧 `timezone`，夜班按当地时间及夏令时换算。机房选项的时区根据地区、国家和城市推导，不再统一返回北京时间。旧 `timezone` 字段保留兼容历史数据；无法识别地区且仅有默认北京时间时，夜班费用返回 `status: pending`，提示确认地区。现有路由、权限和请求响应结构不变，无需迁移。

工程师编辑界面移除参考模板、紧急维护与交通专用配置、项目结算收款及时间试算，改用 `billing_rules.additional_fees` 配置附加费用（最多30项）：

- `id`：唯一标识，1–80个英数字、下划线或连字符；`name`：费用名称，1–100字。
- `mode`：fixed 每次固定金额，或 hourly 按时长计费；`amount`：金额或小时单价，币种沿用工程师规则，空值表示待确认。
- `minutes_source`：fixed 固定时长、actual 记录中填写实际时长、work 本次实际作业时长。
- `minutes`：固定分钟数（0–10080）；`increment_minutes`：向上取整步长（1–1440分钟）。
- `excluded_regions`：兼容历史规则的免收地区。

记录的 `billing_context.additional_fee_minutes` 按费用 id 填写实际分钟数；`excluded_fee_ids` 指定本次不收取的费用。附加费用不参与夜班倍率。一口价不再叠加规则附加费用；现场实报实销通过 `expenses` 调整，是否包含在一口价中由 `expenses_included` 控制。

例如人工50 USD/小时、作业120分钟，加打车100 USD、通勤20 USD/小时（61分钟按30分钟向上取整为90分钟），合计230 USD；本次取消打车则为130 USD。未确认单价或缺少实际时长时返回 pending。

编辑旧工程师时，固定或按时长交通费转换成通用附加费用；保存时清除已移除的专用配置。历史运维记录中的规则快照不自动改写。

沿用工程师创建/更新、运维记录创建/更新及计价接口和原有鉴权；非法字段、重复费用 id 返回422。规则和上下文均存储于既有 JSON 字段，本次无需新增数据库迁移。运维计划列表改为客户筛选，按客户 id 区分同名客户，兼容历史仅保存名称的计划。

## 接口与响应

- `POST /api/v1/remote-assistance/plans`、`PUT /api/v1/remote-assistance/plans/{plan_id}`：保存本次 `customer_pricing`，概览计划响应返回同名字段。
- `POST /api/v1/remote-assistance/plans/{plan_id}/complete`：将计划报价复制到生成记录的费用快照。
- `POST /api/v1/remote-assistance/remote-hands`、`PUT /api/v1/remote-assistance/remote-hands/{item_id}`：接收 `customer_pricing` 和 `billing_context`，后端校验报价结构并计算，响应仍返回 `customer_pricing_snapshot`、`billing_context`、`billing_result`；记录快照不会随客户或工程师档案改价自动改变。
- `POST /api/v1/remote-assistance/billing/preview`：接受同结构报价。一口价时 `rules` 可空，`arrived_at`、`left_at` 可省略；按工时计价仍须有效规则和时间。

一口价试算请求：`{"customer_pricing":{"kind":"fixed","fixed_fee":"500.00","currency":"USD"}}`。成功响应示意：`{"code":200,"data":{"status":"calculated","currency":"USD","total":"500.00","totals":{"USD":"500.00"},"lines":[{"label":"本次施工一口价","amount":"500.00","currency":"USD"}],"notices":[]}}`。

现场 `billing_context.expenses` 最多50项，每项 `{name,amount,currency,note}`。名称1–100字，说明最多500字；金额空为待确认，0为无费用。各规则都可录入携带大件打车、材料费等实报实销；不要重复录入原固定交通费或 `reimbursed_transport`。可通过记录附件上传凭证。通勤继续支持 `actual_commute_minutes`，洛杉矶现场作业按整小时、往返实际通勤按半小时分别向上取整。

多币种按 `totals` 分别汇总，不换汇、不直接相加；此时 `total:null`，`status:calculated`。待确认的价格或报销为 `status:pending`，没有最终totals。一口价已含报销时，报销明细未确认不影响约定一口价合计。报价不自动创建账单或改变结算状态。

写接口沿用对应路由/方法角色权限；试算仅要求登录。无token422、无效token401、无权限403、金额/币种等字段校验失败422；业务错误沿用code400。报价不完整的试算返回HTTP200和pending。

## 部署

执行 `aerich upgrade` 应用 `178_20260923150000_plan_maintenance_quote.py`，仅新增计划报价JSON字段，不删除客户旧字段，不回填历史报价。177及之前的迁移保持兼容；回滚178会移除计划报价字段。已有记录的历史报价快照继续有效。
